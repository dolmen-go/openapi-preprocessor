# Container image and release binaries — design

Date: 2026-10-07
Status: approved; updated after implementation and review with the decisions
taken then (Go toolchain, smoke test script, Podman options, snapshot
annotations, known limitations)

## Goal

Make `openapi-preprocessor` easy to install and use without a Go toolchain:

- a minimal, hardened container image usable with Docker and Podman;
- standalone binaries attached to GitHub Releases.

Both are produced automatically when a version tag is pushed.

## Use cases

Supported:

1. Ad-hoc use on a developer machine: `docker run …` / `podman run …`.
2. Use from CI pipelines by running the image with `docker run` (or by
   downloading a release binary).
3. Copying the binary into another image: `COPY --from=…`.

Explicitly **not** supported: using the image as a CI *job image* (GitLab CI
`image:`, GitHub Actions `container:`), because the image has no shell. The
README documents the alternatives (`docker run` step, `COPY --from`, release
binary).

## Decisions

| Topic | Decision |
|---|---|
| Registry | GitHub Container Registry only: `ghcr.io/dolmen-go/openapi-preprocessor` |
| Tooling | GoReleaser v2 (config + `goreleaser/goreleaser-action`) |
| Trigger | Push of a tag matching `v*`. No `workflow_dispatch`. |
| Binary platforms | {linux, darwin, windows} × {amd64, arm64} |
| Image platforms | `linux/amd64`, `linux/arm64` (single multi-arch manifest) |
| Image base | `scratch` — binary only, no shell |
| Image user | `65532:65532` (numeric: no `/etc/passwd` in `scratch`) |
| Secrets | None beyond the built-in `GITHUB_TOKEN` |
| Go toolchain in CI | `go-version: stable` (latest Go release, for stdlib security fixes), not `go.mod`'s minimum (`go 1.26.0`) |
| SBOM (image) | BuildKit SBOM attestation (SPDX), one per platform, attached to the image index |
| SBOM (archives) | One SBOM file per release archive, generated by syft via GoReleaser `sboms:` |

## Files

| Path | Purpose |
|---|---|
| `.goreleaser.yaml` | GoReleaser config, at repo root (default location, so local `goreleaser check` / `goreleaser release --snapshot` need no flags) |
| `.goreleaser/Dockerfile` | Image definition, used only by GoReleaser (referenced via `dockerfile:`); not at repo root |

| `.github/workflows/release.yml` | Release workflow |
| `.github/workflows/test.yml` | Gains a release-dry-run job |
| `README.md` | New install/usage sections |

## The image

`.goreleaser/Dockerfile`:

```dockerfile
# Used by GoReleaser only (see dockers_v2 in ../.goreleaser.yaml): it copies a
# binary prebuilt for $TARGETPLATFORM and cannot build from a source checkout.
FROM scratch
ARG TARGETPLATFORM
COPY --chown=0:0 --chmod=0555 $TARGETPLATFORM/openapi-preprocessor /usr/local/bin/openapi-preprocessor
WORKDIR /work
USER 65532:65532
ENTRYPOINT ["/usr/local/bin/openapi-preprocessor"]
```

Properties:

- Contains only the static binary (`CGO_ENABLED=0`). No CA certificates or
  tzdata: the tool does no network access and no time handling.
- Binary path `/usr/local/bin/openapi-preprocessor` is stable and documented
  (for `COPY --from`).
- `/work` is the documented mount point and the working directory, so paths
  given on the command line are relative to the mount. BuildKit stores `/work`
  in the image (`0:0`, `0755`); Buildah (Podman) only creates it at run time.
- Read-only in practice: everything in the image is owned by `0:0` and the
  process runs as UID 65532, so it cannot write anywhere in the container
  filesystem even without `--read-only`. A read-only root filesystem cannot be
  enforced by an image; `--read-only` is therefore part of the documented
  standard invocation.
- OCI labels: `org.opencontainers.image.source`, `.version`, `.revision`,
  `.created`, `.licenses=Apache-2.0`, `.title`, `.description`. As GHCR reads
  them from the index for a multi-arch image, `source`, `description` and
  `licenses` are also set as `index:` annotations (`source` links the GHCR
  package to the repository). These annotations are omitted in snapshot
  builds, which are single-platform (`--load`, no index): BuildKit rejects
  index annotations there.
- SBOM: `sbom: true` set explicitly in the `dockers_v2` config (it is the
  default; explicit for visibility). BuildKit scans the final image and
  attaches an SPDX SBOM attestation per platform to the pushed image index.
  For this `scratch` image it lists the Go modules and the Go stdlib version,
  read from the build info embedded in the binary (which `-s -w` keeps).
  Readable with
  `docker buildx imagetools inspect <image>:<tag> --format '{{ json .SBOM }}'`.
  The attestations show up as `unknown/unknown` entries in the index; pulls
  ignore them. buildx's default (minimal) provenance attestation is kept as
  is. Attestations are not signed.

### Image tags

- Always: `{{.Version}}` (e.g. `1.2.3`, `1.0.0-rc.2`).
- Only when the tag is not a pre-release: `{{.Major}}.{{.Minor}}`,
  `{{.Major}}`, `latest`.

## Release binaries

- Build flags: `CGO_ENABLED=0`, `-trimpath`, `-ldflags "-s -w"`.
- No version injection via `-ldflags`: Go stamps the VCS tag into the build
  info when building a clean checkout at a tag, and the existing `version()`
  (`main.go`) reads it from `debug.ReadBuildInfo()`. GoReleaser writes into
  `dist/`, which is already in `.gitignore`, so the tree stays clean.
  `-s -w` strips symbols/DWARF but not the build info.
- Archives: `tar.gz` for linux/darwin, `zip` for windows; GoReleaser default
  name template (`openapi-preprocessor_<version>_<os>_<arch>`).
- Archive contents: binary, `LICENSE`, `README.md`,
  `man/man1/openapi-preprocessor.1` (already committed).
- SBOMs: GoReleaser `sboms:` with `artifacts: archive` runs syft on each
  archive and attaches one SBOM file per archive to the GitHub Release
  (GoReleaser default naming and format). The image is not involved: these
  cover the release archives, including the darwin/windows binaries.
- `checksums.txt` (sha256) for all archives and SBOM files.
- GitHub Release created by GoReleaser with `prerelease: auto` (tags such as
  `v1.0.0-rc.2` are marked pre-release). Changelog from git log since the
  previous tag.

## Release workflow (`.github/workflows/release.yml`)

- `on: push: tags: ['v*']`
- `permissions: contents: write, packages: write`
- Steps:
  1. `actions/checkout` with `fetch-depth: 0`.
  2. `actions/setup-go` with `go-version: stable`.
  3. `go test ./...`
  4. `docker/setup-buildx-action` (no QEMU needed to build: the Dockerfile
     has no `RUN`).
  5. Install syft (`anchore/sbom-action/download-syft`), for the archive SBOMs.
  6. `docker/login-action` to `ghcr.io` with `GITHUB_TOKEN`.
  7. `goreleaser/goreleaser-action` (GoReleaser `~> v2`), `release --clean`.
  8. `docker/setup-qemu-action`, to run the arm64 image.
  9. Post-publish checks on `ghcr.io/dolmen-go/openapi-preprocessor:<version>`
     (the tag without its leading `v`): for each of `linux/amd64` and
     `linux/arm64`, `docker pull --platform` it and run the smoke test (below)
     with `PLATFORM` set and the git tag as expected `-version` output; then
     assert with `docker buildx imagetools inspect` that the SBOM of each
     platform lists `github.com/dolmen-go/openapi-preprocessor`,
     `github.com/dolmen-go/jsonptr`, `github.com/mohae/deepcopy`,
     `go.yaml.in/yaml/v3` and `stdlib`.
- Action major versions follow the style already used in `test.yml`.

## Smoke test (`.goreleaser/smoke-test.sh`)

`.goreleaser/smoke-test.sh <image> [<expected -version output>]`, with
`CONTAINER_ENGINE` (`docker` default, or `podman`), `PLATFORM` (optional) and
`MOUNT_OPTS` (default `ro`). Prints `ok - …` per check, or `FAIL: …` and exits
1. Requires `jq` and GNU `tar`. Checks, in order:

1. Image hardening, on a container created for `$PLATFORM` (`create
   --platform` + `container inspect`: with a multi-platform image, `image
   inspect` would show the host's platform):
   - the user is `65532:65532`;
   - `export | tar -tv`: the binary is `-r-xr-xr-x 0/0`, `work` (if present)
     is `drwxr-xr-x 0/0`, and nothing is owned by UID 65532 or writable by
     others.
2. Processing with the documented hardened invocation (`--rm --read-only
   --network none -v <dir>:/work:ro`), `testdata/` mounted:
   `10-ref-ext` (refs to `../common`) and `11-ref-relative`, output compared
   to `result.json` after normalizing both with `jq -S`.
3. A `$ref` to a file outside of the mount: non-zero exit, `can't load` on
   stderr, nothing on stdout.
4. Files readable only by their owner (copies with modes `0600`/`0700`): not
   readable by the image's default user; readable with the README's
   workaround (`--user "$(id -u):$(id -g)"`, plus `--userns=keep-id` with
   Podman).
5. `-version` is not empty, and equals the expected output if given.

## Release dry run on every push/PR (`test.yml`)

New job, `needs: [test]`, on ubuntu:

1. `actions/setup-go` with `go-version: stable`; `docker/setup-buildx-action`.
2. Install syft (same step as in the release workflow), since the snapshot
   also generates the archive SBOMs.
3. `goreleaser check`.
4. `goreleaser release --snapshot --clean`: builds all binaries, archive
   SBOMs and the images locally, pushes nothing. In snapshot mode
   `dockers_v2` builds one single-arch image per platform and loads it into
   the local Docker daemon, tagged with a platform suffix, without SBOM
   attestation.
5. Smoke test of `ghcr.io/dolmen-go/openapi-preprocessor:<version>-amd64`,
   where `<version>` is read from `dist/metadata.json` (`jq -r .version`).

## README changes

Under "Install", two new subsections.

**Download a binary**: link to GitHub Releases, list of platforms, how to
verify with `checksums.txt`, mention of the per-archive SBOM files.

**Run with Docker or Podman**:

- Standard (hardened) invocation:

  ```
  docker run --rm --read-only --network none -v "$PWD:/work:ro" ghcr.io/dolmen-go/openapi-preprocessor spec.yaml > spec.json
  podman run --security-opt label=disable --rm --read-only --network none -v "$PWD:/work:ro" ghcr.io/dolmen-go/openapi-preprocessor spec.yaml > spec.json
  ```

- Tags: exact `1.2.3`, minor `1.2`, major `1`, `latest`; pre-releases only
  under their exact version.
- Mounting: every file reached through `$ref` (including via `../`) must be
  inside the mount — mount the project root and pass a path relative to it.
  On SELinux hosts, Podman uses `--security-opt label=disable` rather than a
  `:Z` mount, which would permanently relabel the user's files.
- Permissions: the image runs as UID 65532; for files not world-readable use
  `--user "$(id -u):$(id -g)"` (Docker) or
  `--userns=keep-id --user "$(id -u):$(id -g)"` (Podman: `--userns=keep-id`
  alone still runs as the image's user).
- Shell alias example to use the image like a locally installed command.
- SBOM: how to read the attached SBOM with
  `docker buildx imagetools inspect … --format '{{ json .SBOM }}'`.
- `COPY --from=ghcr.io/dolmen-go/openapi-preprocessor:1 /usr/local/bin/openapi-preprocessor /usr/local/bin/`
- CI: GitHub Actions step running `docker run`; note that the image has no
  shell and cannot be used as a job image (GitLab `image:`, GitHub
  `container:`), with `COPY --from` / release binary as alternatives.

- After the first publish, set the GHCR package visibility to **public**
  (new GHCR packages are private by default).

## Acceptance

Validated by tagging `v1.0.0-rc.2`:

- GitHub Release exists, marked pre-release, with 6 archives, 6 archive
  SBOM files and `checksums.txt`; each binary's `-version` prints
  `v1.0.0-rc.2`.
- GHCR has `1.0.0-rc.2` only (no `latest`, `1`, `1.0`), as a multi-arch
  manifest for `linux/amd64` and `linux/arm64`.
- The image has an SBOM attestation for each platform, listing
  `github.com/dolmen-go/openapi-preprocessor`, `github.com/dolmen-go/jsonptr`,
  `github.com/mohae/deepcopy`, `go.yaml.in/yaml/v3` and the Go stdlib.
- The README's standard invocation works on the published image.

## Known limitations (accepted)

- Rootless Docker: the `--user` workaround does not help with files readable
  only by their owner (host UIDs are remapped); `--user 0` works there. Not
  documented in the README.
- No `concurrency` group on the release workflow: two release tags pushed
  together could race on `latest`. Fix: re-run the later tag's release.
- The release workflow checks the image after publishing it; the dry run on
  the tagged commit is the safeguard before the tag.
- `sha256sum` (README "Download a binary") is missing on older macOS, where
  `shasum -a 256 -c` is the equivalent.
- For a pull request from a branch of this repository, the dry run runs twice
  (`push` and `pull_request`), like the other `test.yml` jobs.
- The smoke test's "not readable by the default user" check accepts any
  failure, not specifically "permission denied".
- Podman ignores `--platform` for local multi-platform images in `create`:
  the per-platform hardening checks are reliable with Docker only (as used in
  CI).

## Out of scope

- Docker Hub publishing.
- A rolling `edge`/`master` image tag.
- A shell-based image variant (e.g. alpine) for use as a CI job image.
- A Dockerfile that builds from source (`docker build .`).
- Manual rebuild of an existing release (`workflow_dispatch`).
- Package manager distribution (Homebrew, deb/rpm, …).
- Signing (of binaries, images or attestations).
